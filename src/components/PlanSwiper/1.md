# 番茄钟后端计时架构 操作显示流程规范
## 一、核心总原则（强制遵守）
1.  计时核心全部下沉至 Rust 后端实现，前端所有窗口仅作为**状态渲染层**，不持有任何计时逻辑、不维护计时器。
2.  全局单例机制：同一时间仅允许存在 1 条处于 `running` / `paused` 状态的番茄记录，所有启动操作必须先校验单例。
3.  主窗口内嵌番茄钟、桌面宠物窗共用同一后端状态源，状态变更由后端统一广播，双端实时同步，无状态差。

## 二、操作显示全流程
### （一）启动番茄钟流程（点击 TaskListItem「开始番茄钟」按钮）
1.  前端点击按钮后，向后端发起「启动番茄」请求，传入当前任务 ID。
2.  后端执行全局单例校验：
    - 若已存在 `running` / `paused` 状态的番茄：返回「存在进行中番茄」标识，前端弹出二次确认：**「当前有正在进行的番茄钟，是否结束当前并开始新任务？」**
    - 若不存在进行中番茄：继续校验该任务在番茄钟表中的对应时间内是否存在未完成番茄。
3.  存在该任务的中断保存番茄：直接恢复该记录，状态切换为 `running`。
4.  不存在中断记录：新建 `pomodoro_records` 记录，初始化状态为 `running`，写入 `start_time`、`record_date`、`task_id`。
5.  后端启动全局计时器，每秒更新 `effective_total_seconds`，通过事件总线向所有前端窗口广播最新状态。
6.  前端主界面接收状态，切换为番茄钟执行界面，展示计时、进度、操作按钮。
7.  「专注模式」开关开启时追加步骤：主窗口调用 Tauri API 自动最小化到系统托盘；同时创建/显示桌面宠物悬浮窗，宠物窗订阅后端状态并渲染。

### （二）运行中交互流程
1.  暂停/继续操作：
    - 主窗口或宠物窗触发操作，向后端发送指令。
    - 后端切换状态（`running` ↔ `paused`），控制计时器启停。
    - 暂停的时候`resume_count` 自增 1，记录暂停次数。
    - 后端广播最新状态，两个窗口同步更新 UI。
2.  所有操作指令统一走后端入口，前端不直接修改任何计时数据。

### （三）中断保存流程
1.  用户触发「保存进度稍后继续」操作，向后端发送指令。
2.  后端校验状态为 `running` / `paused`，执行：
    - 状态切换为 `interrupted_saved`
    - 快照当前 `effective_total_seconds` 写入 `interrupt_duration_seconds`
    - 停止全局计时器
3.  后端广播状态变更：
    - 主界面：退出番茄钟界面，返回任务列表，对应任务标记「已保存进度」
    - 宠物窗：关闭/隐藏窗口
4.  中断保存的番茄永久保留，直到用户再次启动该任务恢复、或手动放弃。

### （四）番茄完成结算流程
1.  后端计时达到目标时长，自动触发完成逻辑：
    - 状态置为 `completed`
    - 写入 `end_time`
    - 按金币公式计算 `reward_gold` 并写入记录
    - 停止全局计时器
2.  后端广播完成事件与结算结果。
3.  前端表现：
    - 主界面：展示完成结果、获得金币、休息倒计时
    - 宠物窗：播放完成提示，显示「完成 +N 金币」，切换休息倒计时
4.  完成后不强制召回主窗口，由用户主动点击后还原。

### （五）召回与退出流程
1.  召回主窗口：
    - 双击宠物窗、双击系统托盘图标、右键菜单选择「显示主窗口」，均可触发主窗口还原。
    - 主窗口还原后，宠物窗可选择保留显示或自动隐藏。
2.  关闭宠物窗：
    - 点击宠物窗关闭按钮，仅执行**隐藏窗口**操作，番茄计时继续运行。
    - 可通过系统托盘、主窗口操作重新呼出宠物窗。
3.  放弃番茄：
    - 仅在右键菜单提供「放弃本次番茄」入口，触发后弹出二次确认。
    - 确认后后端将状态置为 `abandoned`，写入 `end_time`，`reward_gold` 置 0，停止计时器。
    - 广播状态变更，主窗口返回任务列表，宠物窗隐藏。

## 三、窗口行为规范
### （一）主窗口
1.  内嵌番茄钟界面为默认展示模式，完整展示任务信息、计时、进度、全部操作入口。
2.  启动番茄后，若开启专注模式，自动最小化至系统托盘，不保留任务栏图标。
3.  主窗口最小化期间，计时逻辑完全由后端维持，不受窗口状态影响。

### （二）桌面宠物悬浮窗
1.  窗口属性：无边框、透明背景、始终置顶、不显示任务栏、不可缩放、默认不抢占输入焦点。
2.  默认位置：屏幕右下角；支持左键拖拽移动，位置坐标持久化到本地配置，下次启动自动还原。
3.  生命周期：随番茄启动而显示，随番茄完成/放弃而隐藏；关闭按钮等价于隐藏，不终止番茄。
4.  多屏适配：记忆所属显示器，分辨率变化时保证窗口停留在可见区域内。

## 四、桌面宠物 UI 与交互规范
1.  UI 结构（优先级从高到低）
    - 顶部：任务名称，单行截断，明确标识当前所属任务，避免误开其他任务。
    - 核心区域（占窗口 60% 高度）：超大号加粗 `MM:SS` 格式倒计时，为窗口最醒目元素。
    - 底部：细进度条，展示番茄完成比例；两侧放置「暂停/继续」「保存进度」两个高频操作按钮。
2.  状态视觉映射
    - `running`：计时数字正常高亮，进度条匀速前进，按钮显示「暂停」。
    - `paused`：计时数字置灰，进度条冻结，按钮显示「继续」。
    - `interrupted_saved`：显示「已保存进度」提示，计时停止。
    - `completed`：显示「完成 +N 金币」，切换为休息倒计时。
3.  交互规则
    - 左键拖拽空白区域：移动窗口位置。
    - 左键双击窗口：快速召回主窗口。
    - 右键呼出菜单：放弃本次番茄（二次确认）、显示主窗口、隐藏宠物窗。
    - 悬停计时区域：浮层展示完整任务名、预估金币、中断恢复次数。

## 五、数据与强制约束
1.  数据持久化：所有状态变更优先写入本地 SQLite，Supabase 同步放后台异步执行，绝不阻塞 UI。
2.  字段严格遵循 `pomodoro_records` 表定义，结算后 `reward_gold` 永久冻结，不可修改。
3.  全局单例强校验：任何启动番茄的请求，必须先校验全局是否存在进行中番茄，禁止同时运行多个。

## 六、MVP 演进边界
1.  当前阶段先落地「后端计时核心 + 主窗口内嵌番茄钟」，单例校验同步落地，解决误点其他任务问题。
2.  宠物窗作为下一阶段迭代，仅需新增渲染窗口，无需修改后端计时核心逻辑。
3.  MVP 阶段不做皮肤、动画、统计等非核心功能。
